# Печать на термопринтерах этикеток без системного стека печати

## Цель

Печатать на USB-принтер этикеток из userspace на macOS, Linux и Windows,
без CUPS, спулера и вендорских драйверов. Сначала текст, потом картинки.

## Слои

```
Label (модель, мм)  →  Encoder (язык принтера)  →  Transport (байты до принтера)
   core/label.rs          core/tspl.rs                core/transport/
```

- **Label** не зависит от принтера. Размер этикетки и зазор, элементы в миллиметрах от
  левого верхнего угла (так этикетка выходит из принтера).
  - `Text` — встроенные шрифты принтера, только ASCII.
  - `Rect` — рамка.
  - `Bitmap` — 1 бит на точку, MSB слева, 1 = чёрный, пиксель = точка принтера.
    Это универсальный путь для картинок, кириллицы и TTF-шрифтов: растеризуем на хосте.
- **Encoder** переводит Label в байты конкретного языка. Сейчас есть только TSPL;
  ZPL/EPL/ESC-POS ложатся рядом тем же интерфейсом.
- **Transport** — `write(bytes)`, `read(quiet)` и `device_id()`. Он ничего не знает о языке.

Выбор энкодера без печати: принтерный класс USB отдаёт IEEE 1284 Device ID
(`GET_DEVICE_ID`), языки перечислены в поле `CMD:`.

## Проверено на AYIN AD230 (macOS)

| Что | Результат |
|---|---|
| USB | `353d:1154`, интерфейс 0, класс `07/01/02` (bidirectional), bulk OUT `0x02`, bulk IN `0x81`, 64 байта |
| Claim интерфейса через nusb | работает без root и драйверов |
| Device ID | `MFG:AYIN ;CMD:XPP,XL;MDL:AD230;CLS:PRINTER;DES:AD230;` |
| `GET_PORT_STATUS` | stall, не поддерживается |
| TSPL `<ESC>!?` | отвечает 1 байтом статуса (`0x00` = готов) |
| TSPL `~!T`, `~!I`, `~!F`, `~!@`, `<ESC>!S` | молчат |
| Печать задания TSPL через bulk OUT | задание принято, статус после печати `0x00` |

`CMD:XPP,XL` — это TSPL-совместимый набор команд.

## Транспорт по ОС

Принцип: если в ОС есть встроенный класс-драйвер USB-принтера, который отдаёт устройство
как обычный файл, используем его. Такие драйверы только передают байты в bulk-эндпоинты,
поэтому на проводе всё то же самое, но ничего не надо отцеплять или ставить, и печать
уживается со спулером. Сырой USB через nusb — только когда такого драйвера нет.
Оба пути для одного принтера одновременно не используются: захват сырого USB из-под
занятого класс-драйвера оборвал бы чужое задание.

| ОС | Основной путь | Запасной путь | Что нужно пользователю |
|---|---|---|---|
| macOS | nusb (IOKit), `claim_interface` | — | ничего |
| Linux | `/dev/usb/lpN` (`usblp`): `write`/`read` + `poll`, Device ID через `LPIOC_GET_DEVICE_ID` | nusb (usbfs), если `usblp` нет; чужой драйвер отцепляется и возвращается при закрытии | группа `lp` (`sudo usermod -aG lp $USER`); для запасного пути — udev-правило |
| Windows | `usbprint.sys`: `CreateFile` на `GUID_DEVINTERFACE_USBPRINT`, overlapped `WriteFile`/`ReadFile`, `IOCTL_USBPRINT_GET_1284_ID` | nusb, если на устройстве WinUSB | ничего, без прав администратора |

Совсем без разовой настройки на Linux не обойтись: файлы устройств по умолчанию
принадлежат root или группе `lp`. Root в рантайме не нужен.

Код: `crates/core/src/transport/` — `usblp.rs`, `usbprint.rs`, `raw_usb.rs`.

udev-правило для запасного пути на Linux:

```
SUBSYSTEM=="usb", ATTRS{idVendor}=="353d", ATTRS{idProduct}=="1154", MODE="0660", TAG+="uaccess"
```

## Открытые вопросы

- Бэкенды `usblp` и `usbprint` пока только компилируются: на Linux и Windows с железом не проверены.
- Выбор принтера: сейчас берётся первый найденный.

- Кириллица: встроенные шрифты её не умеют. План — растеризация текста на хосте в `Bitmap`
  (например, `fontdue` или `ab_glyph`); `CODEPAGE` у клонов ненадёжен.
- Зазор между этикетками сейчас захардкожен на 2 мм; нужна настройка или калибровка (`GAPDETECT`).
- Статус во время печати: опрашивать `<ESC>!?`, пока не уйдёт бит `printing`.
- Размер этикетки и dpi должны стать настройкой профиля принтера.

## Структура и GUI

```
crates/core   label, tspl, transport, render (растеризация текста), fonts (вшитая Helvetica)
crates/cli    labelprobe — отладочный CLI
crates/gui    itmo-labels — приложение на egui
assets/fonts  Helvetica Regular и Bold (проприетарные, репозиторий приватный)
```

Текст растеризуется на хосте (`render`): шрифт → однобитный битмап на всю этикетку при
203 dpi → `BITMAP` в TSPL. Поля 2 мм, строка по центру, кегль подбирается автоматически
или задаётся вручную. Portrait — строка вдоль короткой стороны этикетки, landscape — вдоль
длинной; если для этого строку надо развернуть относительно головки, она поворачивается
на 90° по часовой.

Файлы приложения лежат в каталоге настроек ОС (`~/Library/Application Support/itmo-labels`,
`%APPDATA%\itmo-labels`, `~/.config/itmo-labels`):

- `sizes.toml` — список размеров, создаётся из встроенного при первом запуске,
  перечитывается при сохранении;
- `state.toml` — последнее состояние окна.

Отладка: debug-сборка с `ITMO_LABELS_SCREENSHOT=out.ppm` через 3 секунды сохраняет
скриншот окна и закрывается.
